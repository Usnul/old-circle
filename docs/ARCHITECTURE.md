# Architecture and current limits

## Ownership

Meep supplies ECS storage, physics, BVHs, navigation, rendering, particles, audio, serialization and networking. `Actor` is gameplay data, not an object hierarchy. `Transform64`, `RigidBody` and `Collider` hold spatial state. Actor string IDs are stable across server snapshots; Meep entity IDs are local to each dataset. The presentation dataset is separate from simulation so rendering cannot author damage or progression.

`GameWorld` is the shared 60 Hz simulation used by the server and browser Worker. The main thread renders and sends intent. A 30 Hz `SharedSession` advances two physics steps per network tick. Meep `NetworkSession`, `SimAction`, action history and authoritative reconciliation implement connected prediction and replay.

The replication dataset keeps a host-only `WorldFrame` for rollback and a separate `WorldFrame` for each recipient, alongside its owned `CharacterFrame`. Recipient views include actors within 96 m, retain them to 112 m to avoid boundary churn, and cap actors/projectiles/events at 96/128/128. Nearby projectiles retain their owners even outside that radius. Host-only patrol paths and decisions are omitted. The local actor travels through its owned component; the nearby view carries only its identity placeholder, which presentation and prediction replace with the complete owned state.

`FrameAdapter` schema 3 uses field ordinals, exact integer/Float64 values and native Meep LZ4 blocks. It bounds decoded bytes, nesting and collection sizes without quantizing simulation state. `WorldPatchAction` carries changed fields, arrivals, removals and effects against each recipient's own baseline. After host rollback, the first fresh frame replaces each view completely, preventing stale enemy health or inventory after corrected history. The initial-snapshot adapter emits only the recipient's view and owned character through Meep's native snapshot format (MEEP-011). Physics contact caches are reconstructed rather than serialized. Meep's interpolation and transform codec drive characters, corpses and the camera from one presentation timeline; GPU skinning and combat sockets share Blender clips.

## Connection lifecycle

The Worker stamps presentation snapshots with their simulation frame and an authority epoch. Meep's `RenderPlayout` and `AdaptiveRenderDelay` advance a continuous playhead with a bounded two-to-four-frame buffer, so uneven message arrival does not directly change walking speed. Bodies, weapons, ragdolls and the camera sample that same timeline. Authority changes reset the timeline instead of blending unrelated world clocks.

Camera collision shortens the view immediately and eases it back out after clearance. Below 2.2 m, the local pilgrim and carried equipment fade through native material transparency; at 1 m they are hidden. The lantern continues lighting the room. Instance-owned material clones are reused across wall contacts and restored before weapon replacement, ragdoll transfer or pooling, leaving shared outfits and other players unchanged.

1. The Worker starts the local Meep world immediately, using its saved character if available.
2. A small JSON handshake identifies the protocol, player and returning character. The server validates shape and finite values and trusts the character's progression, as specified by the game design. It never imports the client's world snapshot.
3. The server allocates a peer and a fresh network ID. After the client's session is ready, a second character snapshot covers movement during initialization. Meep's `WebSocketTransport` takes over binary traffic.
4. Server-authored presence actions record arrivals, departures and character imports in Meep's action history. This matters: unrecorded between-tick mutations can be overwritten when late input causes replay.
5. The client acknowledges its installed initial snapshot through a Meep reliable command. The server then starts its scoped action stream from that frame, avoiding a race with older world history. Both peers acknowledge large packet bursts before they overflow the channel's 32-bit acknowledgement window.
6. The client transmits only its owned character's actions/state. Prediction borrows the Worker's already-running `GameWorld`; connection setup does not rebuild terrain or static colliders. It replays the character and nearby collisions while the host makes enemy decisions. Enemies leaving scope are cached at their last received state. A new authority epoch discards the old offline branch; unseen NPCs use authored initial states until their region is received. On disconnect, cached enemies return to the same physics world and remote players leave. The replication session owns only its network dataset.
7. On socket loss, or after one second without authoritative advancement following a five-second initial synchronization grace period, the warm local simulation resumes full authority. Connection attempts resume every five seconds. Rejoining carries the current character, including velocity, crouch, mantle and attack/animation phases; the authoritative world replaces local enemies, objects, projectiles and clock.

Retired replication rows remain allocated for more than the 64-frame history window. Reusing a local entity ID too early lets prior-byte restoration target a different character. Player network IDs increase for the life of a server process. Peer IDs are released after Meep handles transport disconnection.

`GameSocketTransport` subclasses Meep's WebSocket adapter and copies outgoing packet bytes before handing them to the socket. Node `ws` can retain queued byte views after `send` returns, while Meep immediately reuses its packet scratch buffer. The copy preserves packet ownership without replacing Meep's protocol. MEEP-004 records the reproduction and the transport regression test.

World snapshots retain up to 1.5 seconds / 256 effects so a presentation frame cannot miss a one-tick spell event. The owned character also presents predicted nova events immediately. Stable nova action IDs deduplicate predicted and confirmed effects in the Worker; presentation consumes each delivered snapshot once, including when its authoritative tick has not advanced. This bounded history is a baseline, not a durable event log for large encounters.

The server defaults to eight players and one active socket per character. `OLD_CIRCLE_MAX_PLAYERS` permits 1–16; a returning character can replace its connection at capacity. A socket exceeding 512 KiB of queued outgoing data closes so its client can continue locally. Browser tabs in the same profile share the character ID; use distinct profiles for different players. There is no account authentication or cross-device character service. This is a local development server, not a public identity/security boundary.

## Combat and progression

Supported characters cancel gravity and follow the contact plane through their Meep rigid-body velocity. Ground adhesion accounts for capsule curvature on slopes, settling to contact without pushing downhill. Character colliders have zero friction: motor braking holds a resting character, while surface friction would otherwise oppose the commanded walking speed. Knockback and airborne motion retain dynamic physics. Sprint consumes 18 stamina per second without simultaneous regeneration. Exhaustion persists in replay and character saves until Shift is released with 25 stamina (or a quarter of maximum) recovered; resting and respawning reset it. Journal attribute eligibility refreshes from every presented snapshot, including while the shared world keeps running behind the menu.

Melee's shared `weaponPose` matches the Blender blade pivots. Meep sphere sweeps test the blade and sampled travel between ticks, with a per-swing victim set. A hound uses a short muzzle segment. Projectiles sweep their travelled distance; arrows have gravity. Nova uses a Meep sphere overlap followed by line-of-sight tests and shows its radius with particles and a ring. Knockback is a Meep impulse, with temporarily reduced movement control.

The engine's current public shape-cast implementation cannot sweep against concave heightfields. The game adapter uses seven parallel Meep rays for those targets. This is an approximation, recorded in MEEP_DEFECTS.md. Neither capsule actors nor sampled blade sweeps are per-triangle anatomical collision.

Boss progress resets only when no living player remains near the encounter home. Living players within reward range share boss rewards and seals. Normal enemies respawn after three minutes and bosses after twenty minutes, provided no living player is nearby. Starting origins only set inventory and attributes. Weapons have ownership, arrow costs and resource costs. Armor reduces physical or magical damage and knockback, modifies walking speed and hearing range, and sets stamina/focus regeneration. Weapon reinforcement is owned per weapon and consumes embers at a safe hearth; ranks are limited by recovered seals. Equipment commands share the reliable input sequence with attribute purchases, so replay applies each command once. PvP kills produce no enemy rewards.

The Bellkeeper’s Reliquary extends the hollow with seven connected spaces on two floors. Its authored floor plan supplies Blender masonry, convex collision, encounter homes, room names and layered navigation. Lower and upper surfaces remain distinct at the same X/Z. Native room-graph paths split folded navmesh queries when needed. The Quiet Flame is a personal, once-only relic; it grants embers and one permanent flask slot. Character snapshots and replay carry relic ownership, and resting or respawning restores the derived flask capacity.

Five further regional dungeons share that authoring pipeline: the Rootbound Cloister, Ashen Cistern, Listening Observatory, White Ossuary and Uncrowned Archive. Each adds five authored guards, a distinct floor arrangement, a graded branch road and a personal charm. The cistern descends below its court and returns by a second stair; the observatory climbs three storeys before a staged descent. Every room pair is checked through native navigation, and the character motor walks each entrance-to-reward route and return. The six dungeons contain thirty guards in total. Charm ownership derives from personal relics, with one equipped inventory field; switching at a safe hearth replaces the previous effects. Damage, focus costs, regeneration and movement consume the same shared modifiers during local simulation, authoritative play and replay.

## Persistence and versions

The server writes a Meep `BinaryBuffer` containing disk-save version 1 and the world payload, then atomically renames the temporary file. Disk-save versions are independent of network protocol 7, which adds the sequenced charm command to protocol 6's scoped recipient views and packed binary schema 3. Earlier protocols introduced dungeon relics, keeper hazards, sequenced equipment commands and LZ4 framing. Stable hazard keys and per-victim hit ledgers survive ECS reconstruction and prediction replay. Restart restores NPC and world state; disconnected players are not resurrected. Browser saves contain only the character allowlist. `contentVersion` migrates older elevations by lifting positions and checkpoints above raised terrain. New optional character fields have explicit import defaults. World-content version 5 adds the five regional dungeons, preserves authored upper-floor homes and merges newly introduced encounters into older disk saves. `migrateInventory` maps old free-text armor to mail, restores seal-earned armor, defaults reinforcement ranks to zero and removes charms without a matching owned relic. Disk saves and the character envelope remain version 1; the migration also runs when restoring an older server world. Add a migration before changing a released schema.

## Performance and remaining work

Scenery decodes and activates nearby detail and preserves authored distant terrain and landmark silhouettes. `WorldStream` selects full terrain within 120 m of its bounds, trees within 80 m and large architecture within 105 m, with 25 m of hysteresis. Small plants enter at 50 m and leave at 62 m. A ready replacement is created before its previous native scene entities are removed. Scene work yields after sixteen replacements or three milliseconds, and model I/O permits four concurrent requests. Lights, embers and banner animation activate only near the player. The complete collision world remains resident, so visual loading never determines whether a floor or wall exists.

Before play begins, `GeometryCache` warms the complete serialized asset catalogue into browser CacheStorage, keyed by a compiled content fingerprint. This preserves offline travel to previously unseen regions after the server disappears. The current catalogue is 113.8 MiB including both detail levels. Those bytes are decoded only when needed; if browser storage is denied or full, a finite in-memory byte cache preserves the same session behavior. Successful warming retains at most the current and previous cache revisions. This reduces active scene/decoded work, not the first-install download. The workshop's active and visited counters refer to decoded geometry, not the disk cache.

`build_lods.py` authors 66 distant representations in a separate editable Blender file. Terrain changes from 3,200 to 392 triangles per tile while preserving every full-detail perimeter vertex and its height; all 48 mixed-detail borders have a serialized-geometry regression. Simple closed masonry prisms retain their faces, while complex shapes and bevelled trim are decimated. Native rays compare floor and wall coverage in both dungeon representations. Native Meep meshlets, BVHs, scene membership and terrain splatting render both levels. No runtime geometry simplifier or second renderer is involved.

Dungeon stonework shares two 1,024-pixel tileable PBR sets: staggered dressed masonry and worn flagstones. Six mineral palettes come from the shared dungeon catalogue. Albedo, normal and roughness/metalness maps add 4.8 MiB of PNG files and are reused across all twelve materials. Blender source meshes retain world-scale UVs and packed maps; the distant meshes preserve those UVs through decimation. Architectural material changes leave collision and navigation unchanged.

The five wearable outfits use continuous weighted sleeves and trousers, shaped cuirasses, split coat hems and flexible boot tops. Light outfits frame a recessed face with an open hood and a shoulder cowl; plate outfits use forged helmets. These Blender meshes share the established human bone order and bind transforms with the keepers. The 129-clip animation catalogue remains unchanged, preserving movement, combat sockets and ragdoll transfer. Geometry refinement does not change armor statistics or physics bodies.

Unused scenery leaves the active model table after five seconds. Because Meep's BLAS arena does not reclaim removed trees, the current adapter keeps one registered geometry object per visited model (MEEP-012). This bounds repeated travel by the finite versioned asset catalogue; it does not reclaim GPU geometry for departed regions. The workshop distinguishes active geometry bytes, visited geometry bytes and native GPU allocation. Character and banner skins are retained and reused to avoid the separate native matrix allocation issue. A future supported native residency API can replace this cache without changing content or scene selection.

The 2 m outdoor navigation surface and .5 m layered dungeon surfaces are baked binary assets. Meep NavMesh tiles use a 32-entry least-recently-used cache; evicted tiles rebuild from the loaded indexed source without collision rasterization. Navigation source bytes and dungeon meshes remain resident. Replication is scoped and bounded, but the host still clones its complete simulation for rollback. Encounter balance, richer regional art, persistent identity and broader operating measurements remain necessary.

Browser workshop checks on the RTX 4090 visited all six hearth regions with combat frozen: 967–1,173 of 3,826 props were active, with 14–16 detailed terrain tiles and 33.3–44.6 MiB of decoded active geometry. These are fixed-view observations, not minimum-hardware or combat frame-time benchmarks. In a separate browser run, stopping the asset server before visiting the crown still allowed its detail and the upper reliquary chamber to load. Returning between those locations retained 117.4 MiB of native GPU geometry allocation without another increase; the visited source cache held 58.8 MiB. Longer rendered combat sessions still need separate coverage.

Local budget measurements on Windows / Node 24 / Ryzen 9 9950X, 2026-09-10, used the populated 79-NPC world and walking clients near the opening hearth. Each scenario covered three simulated seconds after a short warm-up, with packet processing included and rendering disabled; these brief runs include JIT and collection variation. The host has 33.3 ms per network tick. Sixteen players nearly exhaust that budget; eight is the default to leave room for combat and delayed-input replay.

The renderer uses native meshlets/BVHs, clustered lighting, GPU particle graphs, volumetric media and the native environment background. Meep's Hosek sky supplies 64 HDR environments prepared during loading, so changing the clock does not run atmosphere sampling loops during movement. A directional light follows the sun or opposing moon. Meep's histogram-based automatic exposure remains enabled and adapts between outdoor light, night and interiors; the lantern and regional lights provide local contrast. Geometry, weighted skins and animation clips are authored in Blender and converted at build time. Meep skeletal animation drives full-body locomotion and attacks; a separate Meep physics world handles jointed corpses. A Meep behavior tree drives enemy patrols and awareness. Meep’s local fluid field drives airborne effects and Blender banner blends. Native decals project foot contacts and keeper warnings onto the world. Native Trail3D geometry follows the displayed blade during its damage window and ordinary projectile heads. At most 24 nearby trails live at once; their knots fade after emission ends and clear on replay discontinuities or authority changes. Texture compression remains to be integrated. Sopra plays positional events and ambience through native acoustic simulation; acoustic pathing is explicitly disabled.

The acoustic index uses the same 4,688 static bodies as physics, with a native triangle surface supplying the missing heightfield raycast (MEEP-013). The shipped 1,033-probe field contains 256-ray, three-band reflection bakes at playable listener heights. Runtime selects the nearest visible probe, preserving separate floor and wall regions. Up to 24 spatial voices receive native occlusion, material transmission and air loss at 20 Hz. The effects bus sends to native probe convolution and returns through master gain; broad wind stays dry and attenuates under shelter. Local sky rays control wet amount and cap open-air tails at .35 seconds, rising to two seconds indoors. No visibility graph or corner-leak send is created.

A Node-only 24-source sweep on the development Ryzen 9 9950X measured native solve p95 between .29 and 1.00 ms across the opening, two reliquary floors and the wood. Browser checks exercised fire, spells, impacts and room transitions without console errors. Native impulse synthesis still happens on the main thread when a changed probe requires a new tail; one observed cave transition cost 17.9 ms including that synthesis. The two-second cap and change threshold bound this cost, but it remains a transition hitch risk. Audio-node regression tests verify spectral transmission and routing; listening approval is separate.

The current transport is reliable WebSocket for local development. Meep itself cautions against it for latency-sensitive state because of TCP head-of-line blocking. Move the same session protocol to Meep's WebTransport or WebRTC transport for internet play. The local authority currently calls the shared simulation directly inside the Worker; it does not run a second network session over MessagePort.

## Verification

Vitest checks physics locomotion, crouch clearance, melee range and duplicate hits, projectile tunneling/cover, nova cover/range, knockback, mutual PvP, boss reset, inventory saves, character-only world replacement, SH coefficients, Meep loopback prediction and real WebSocket disconnect/reconnect/server persistence. Real-clock network tests run sequentially so CPU-heavy rollback tests cannot starve their connection deadlines.

`world:check` builds Meep navigation and exits unsuccessfully if a designed road or dungeon reward route has no sampled path. Browser workshop captures are separate visual evidence: the navigation report cannot judge artistic quality. Network regressions cover separate recipient snapshots, scope transitions, exact packed numbers, saturated payloads, malformed record limits, backpressure and delayed/lost/reordered input without duplicate purchases.
